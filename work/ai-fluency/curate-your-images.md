## 2. Real captures — kept, and how they got clean

Every project folder in `public/projects/` holds **cropped, browser-chrome-trimmed screenshots of the actual running app** (ACRA Lab dashboard, Aegix AI verdict screens, CafèSync's live order board, etc.) — 3 to 9 shots each, picked from a larger raw pool in `img/`. None are stand-ins or AI mockups; every one is a real screen from a real deployed project.

## 3. The connective tissue — why I didn't generate anything

The brief says: generate connective tissue (hero texture, icons) in one consistent style. I looked at what my hero actually needed and decided **not** to generate an image for it. My hero background is a canvas particle grid that lights up near the cursor, and my cursor itself is a small ring-and-dot — both driven by a few lines of JS, not a picture. A generated texture image would have to be re-prompted every time I tweak the color palette, and it would be one more static asset competing with real project screenshots for attention. Code that reads my actual CSS variables can never drift out of style, so I kept it code instead of image.

## 4. Rejected — real judgment, from my own raw screenshot pool

I compared the raw capture pool (`img/ACRA/`, 10 screenshots) against what actually shipped to `public/projects/` (3 screenshots: `acra.jpg`, `acra-2.jpg`, `acra-3.jpg`) and found two real rejections:

- **`Screenshot 2026-07-05 234557.png` — rejected for wrong subject.** This file lives in the ACRA folder but is actually a screenshot of my *portfolio site's* About section and the zeref-bot chat widget — not the ACRA product at all. It must have been dropped into the wrong folder while I was capturing multiple projects in one sitting. Keeping it would have meant a "work" image that doesn't show the work.
- **`Screenshot 2026-07-05 235604.png` — rejected as a redundant duplicate.** It's the same ACRA Lab empty-state screen as the kept `acra.jpg`, just captured at a slightly different browser width a few seconds apart. It adds no new information about the product and would read as accidental repetition in a gallery — one clean capture of a state says everything both would say.

Neither rejection is about polish or taste — both are about whether the image actually earns a spot: one showed the wrong thing entirely, the other said nothing the kept image hadn't already said.

## 5. Where I chose (or need) a real photo over anything generated

**My rule:** anything that is *me* gets a real photo, never a generated one — a generated face would undercut the exact "I show real, verifiable work" claim my whole portfolio proof statement rests on.

**Honest gap:** I currently have **no photo of myself anywhere in the repo** — no headshot on the About section, no avatar. That's not a curation choice, it's a missing asset. Fixing it means taking or picking one real, plain photo (not generated) and adding it to `src/data.js` → `profile`. Until then, the About section correctly has no face rather than a fake one.
